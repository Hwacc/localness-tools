# JSON shapes

`platform` in field names, kinds and `source` values means remote, `local` the locale files. In `diff --json`, `platform` is the published remote text, `draft` the remote working text and `onPlatform` whether remote has the key.

`diff`, `pull`, `push`, `sync` and `apply <id>` also have `config`: the config file used, relative to the working directory with `/` separators (for example `apps/web/localness.config.json`).

- `diff --json`: `{ config, sourceLocale, locales, content, hasBase, files, differences: [{ locale, key, kind, local, platform, draft, base, onPlatform, target, locations, dirs }] }`; `files` maps each locale to its file paths, one per configured directory; `target` is `{ dir, by }` (`by`: `existing`, `namespace`, `key`, `fallback` or `unrouted`, then `dir` is null); `locations` are where this locale has the key (`{ dir, relativePath, value, path }`), `dirs` every directory holding it in any locale.
- `pull --json`: `{ config, dryRun, files: [{ locale, dir, relativePath, created, set, removed, keptInArray, skipped }], kept, unrouted, duplicates, dirs, left }`; `sync --json` is `{ config, pull, push }` with the same `pull` part (no `config`, no `left`) and the `push --json` shape (no `config`). `unrouted` and `duplicates` are `[{ locale, key, platform, dirs, locations: [{ dir, relativePath, value }] }]`, `dirs` the directories `--into` accepts. `skipped`: new keys the file's structure cannot take, including any under an existing array; `keptInArray`: keys `--prune` would remove that sit in an array, left in the file. Exit code 1 when either is not empty.
- `push --json`: `{ config, id, path, expiresAt, sourceLocale, release, keys: [{ key, create, locales: { <locale>: { text, platform, draft } } }], blocked, warnings, leftOut }`; `id` is null when there is nothing to push; `release` is the name new keys get, or null.
- `apply <id> --json`: `{ config, id, written: [{ key, created, locales }], failed }`; `apply --json` without an id lists the saved plans of that config: `[{ id, createdAt, expiresAt, keys }]`.
- `match --json`: `{ matches: [{ text, keys: [{ source, key, sourceText, ... }] }], convention, namespaces }`. `matches` has one entry per text in order; a match is the same source text after whitespace normalisation. `source: "platform"` keys also have `id`, `draft` and `releaseIds`; `source: "local"` keys exist only in the source-locale file and are not pushed yet. `convention` is `{ prefix, separator, style, maxDepth, guidance }` (`style` is `snake_case`, `camelCase` or `none`) (`prefix` has no trailing separator, `''` means none; `guidance` is the project's naming advice or null), or null when the server predates it. `namespaces` lists the project's namespace names, relative to the prefix.
- `review start --json`: `{ id, url, rows, openedIn }`; `rows` is the number of texts, `openedIn` is `browser` or `editor`, and `url` is null when the page opened in the editor. Input file: `{ items: [{ text, file?, line?, key? }] }`.
- `review start --kind resolve --json`: the same shape, `rows` counting keys; or `{ id: null, rows: 0, openedIn: null }` when nothing needs a decision. No input file. Pass `--config` when the repo has several configs; the commands in the result then carry it.
- `review start --kind plan <id…> --json`: the same shape, `rows` counting keys across the plans. No input file. Pass `--config` when the repo has several configs.
- `review wait <id>` for an extract review: `{ id, status, items }`; `status` is `pending` (also has `url`; run it again), `approved` or `cancelled` (`items` empty). Items: `{ index, text, file, line, action, key, source }`, `action` is `reuse`, `create` or `skip`; `skip` has no `key`, only `reuse` has `source` (`platform` or `local`).
- `review wait <id>` for a resolve review: `{ id, kind: "resolve", status, items, commands }`. Items: `{ key, locale, kind, action, into? }`, `action` is `pull` (take remote; `into` is the directory when the key had no place), `push` (plan sending local), `prune` (delete from the locale file) or `skip`. `commands` are the shell commands for the chosen actions, pulls before pushes, empty when cancelled or everything was skipped. A `push` command carries `--json` and only writes a plan.
- `review wait <id>` for a plan review: `{ id, kind: "plan", status, plans, commands }`. `plans`: `{ planId, applyId, keys, left }`. `applyId` is the plan to apply, null when that plan was rejected or emptied, and it differs from `planId` when the person dropped keys or locales. `left`: `{ key, locales }` that were dropped. `commands` are `localness apply <applyId> --json`, empty when cancelled. `cancelled` leaves the plan files untouched.
- `blocked` in `push --json`: `[{ locale, key, reason, violations? }]`; `reason` is `no-source-text`, `reserved-name`, `key-name` or `duplicate` (the key is in several directories with different texts), and `violations` lists what a `key-name` key breaks: `prefix`, `charset` or `segment`.
- `warnings` in `push --json`: `[{ key, violations }]`, new keys that are still created but miss a suggestion: `separator`, `case` or `depth`.
